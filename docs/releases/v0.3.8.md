## 0.3.8 呼吸相位修正

针对 0.3.7 重复发送灯效命令造成呼吸跳变的实机反馈，取消正常运行时的 LED 定时重发，也取消仅因缺少 ACK 而重复呼吸命令。

- 同一设备、同一有效灯效发送一次后保持静默；收到 ACK 与已发送但未确认分别记录。
- 切换灯效前先执行已有的只读 HID 通信检查。明确尚未调用 LED 写入或设备明确拒绝时才退避重试；进入写入后的系统错误、缺少 ACK 或子进程中断都无法证明设备未执行，不假定命令没有生效。
- Windows 明确报告断开后重新连接，或收到真正的系统恢复通知时，重新应用当前最新灯态一次。普通电量恢复、系统时钟校正和保存无关设置不会重启灯效。
- LED 回执等待与电压查询分开，延长单次纯等待时间，等待时不再次发送 LED 命令。
- 暂停/恢复及手动重新连接仍可要求重新应用；任务完成倒计时、原有声音轮次和 Ubuntu hooks 语义不变。

新增模拟灯会在每次呼吸命令实际到达时重置相位；回归测试检查连续 10 分钟的发送次数和相位起点，覆盖有 ACK、无 ACK、多个周期、明确失败及重连。

目前已验证的协议没有当前灯态/相位读回。对于“命令可能丢失，但调用成功、缺 ACK 且未观察到连接变化”的情形，不能同时保证零重复启动和所有失配自动恢复，仍保留手动重新应用。测试和云构建不等于用户实体灯验收。

只需升级 Windows 安装包；已有 Ubuntu 0.3.5/0.3.6 agent、hooks 和任务记录继续兼容。安装前从系统托盘退出旧版 AI Light。
